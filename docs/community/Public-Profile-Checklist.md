# Public engineering profile checklist

The goal is to make HWcontrol2.0 discoverable through genuine engineering work.

## GitHub

- Keep the README accurate and Beta status explicit.
- Keep Wiki documentation synchronized from docs/wiki.
- Publish reproducible releases with checksums.
- Keep CI results visible.
- Maintain contribution, support and security documentation.

## GitLab

The GitHub repository is the source of truth. The configured GitHub Actions mirror publishes branches and tags to:

https://gitlab.com/lordkeremello45/HWcontrol2.0

The mirror workflow must remain green; it should not become a second source of truth.

## Google Developers

Use the personal Google Developers profile for genuine developer identity and project references.

Recommended profile content:

- HWcontrol2.0 as an open-source project;
- Flutter/Dart, Go, C++, CMake and CI/CD technologies actually used;
- hardware monitoring/control and cross-platform engineering;
- links to the GitHub repository and project website.

Do not claim certifications, memberships, production deployments or hardware support that have not been verified.

## Stack Overflow

Build reputation through useful technical questions and answers. Prefer subjects such as:

- localhost IPC security;
- cross-platform hardware abstraction;
- CMake/Go/Flutter integration;
- release integrity and packaging.

Do not use Stack Overflow as an advertising channel.

## Release evidence

A strong public project trail should connect:

GitHub source → CI validation → GitHub Release assets → checksums/attestations → GitLab mirror → Beta feedback → issue tracking.

Each link in that chain should point to real, current evidence.

## Manual account actions

Google Developers profile edits and Stack Overflow posts require the owner's account session. This repository contains the technical material and profile checklist, but those external account actions should be performed from the user's own accounts.
