# Building from Source

HWcontrol2.0 is a multi-language repository. Build only the components needed for your task; not every helper is required for core hardware monitoring.

## Prerequisites

- CMake 3.16+ and a C++17 compiler
- C++20 compiler for the independent Game Core target
- Go 1.22 or the version declared in bridge_service/go.mod
- Flutter/Dart version matching the CI workflow
- Optional: .NET 8 for the Windows hardware-identification helper
- Optional: Rust stable, GNAT/SPARK and Node.js for their respective supporting components

## Native C++ components

The root CMake project fetches pinned llama.cpp and miniaudio sources through FetchContent. CUDA acceleration is opt-in and disabled by default.

```sh
cmake -S . -B build -DGGML_NATIVE=OFF -DGGML_CCACHE=OFF
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

The root project builds ai_core and audio_core; hw_game_core is a separate C++20 foundation and can be disabled with HWCONTROL_BUILD_GAME_CORE=OFF. These are native helpers/components, not the current Go hardware-control runtime.

## Go bridge

```sh
cd bridge_service
go vet ./...
go test -count=1 ./...
go build -buildvcs=false -trimpath -o ../bridge-service ./src
```

The Go bridge is the current hardware telemetry and supported-control boundary.

## Flutter dashboard

```sh
cd gui_dashboard
flutter pub get
flutter gen-l10n
flutter analyze
flutter test --no-pub
```

Platform-specific Flutter runner files are generated by the release/validation workflows where required.

## Optional supporting components

Windows hardware identity helper:

```powershell
dotnet build .\lib\hardware-identification\HWControl.HardwareIdentification.csproj --configuration Release
dotnet run --project .\lib\hardware-identification\HWControl.HardwareIdentification.csproj --configuration Release -- --self-test
```

Rust telemetry analyzer:

```sh
cargo test --manifest-path tools/telemetry-analyzer/Cargo.toml
```

Website:

```sh
cd website
npm install
npm test
npm run build
```

## Runtime models

Gemma GGUF weights and Piper binaries/voice models are optional runtime inputs. They are not fetched by CMake configuration and are not required for core monitoring. Verify their origin, license and checksum before use.
