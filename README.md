[![HWControl Website](https://img.shields.io/badge/HWControl-Website-111827?style=for-the-badge&logo=googlechrome&logoColor=white)](https://lordkeremello45.github.io/HWcontrol2.0/)

HWcontrol2.0 is an open-source, cross-platform desktop hardware monitoring and control suite built around a Flutter/Dart dashboard, an authenticated localhost Go bridge, and a native C++/CMake engine.

> **Current channel: Beta.** Hardware support and control capabilities depend on the operating system, drivers, and detected hardware. Unsupported control paths remain monitor-only.

## What it does

- CPU, memory, disk, GPU and fan telemetry where exposed by the OS/driver
- Temperature history and configurable temperature alerts
- Hardware-control commands for supported platforms/devices
- Performance / Balanced / Quiet profile support where available
- Game Mode
- Local user profiles and fan-curve configuration
- Secure loopback communication between the dashboard and bridge
- Bridge diagnostics and hardware capability reporting
- Optional local AI support; the core application does not depend on the model being installed
- Cross-platform build, package, checksum and provenance validation in GitHub Actions

## Installation

### Windows

Use the guided Setup.exe for normal users. The MSI remains available for managed deployment, and the portable ZIP is intended for users who do not want an installed Windows service.

### macOS

Use the Apple Silicon PKG or DMG from the macOS Beta release.

### Linux

Use the DEB on Debian/Ubuntu-family systems, or the portable TAR package when appropriate.

For detailed platform instructions, see the [Wiki](https://github.com/lordkeremello45/HWcontrol2.0/wiki).

## Security and release integrity

The local bridge listens on loopback and authenticates commands with HMAC-SHA-256. Release workflows publish SHA-256 manifests and GitHub artifact attestations where configured.

Checksums and attestations provide integrity/provenance evidence; they are **not** substitutes for OS-trusted publisher signing. Windows Authenticode and Apple Developer ID/notarization are only claimed when the corresponding trusted credentials and verification steps are actually present.

See [SECURITY.md](SECURITY.md) and the [security documentation](https://github.com/lordkeremello45/HWcontrol2.0/wiki/Security-and-Signing).

## Beta feedback

Beta feedback is intentionally routed through Google Forms → Google Sheets → Apps Script → GitHub Issues. The integration filters contact/private fields, adds duplicate protection and retries, and does not require feedback submitters to expose bridge credentials.

- [Beta feedback integration setup](integrations/google-feedback/README.md)
- [Google feedback automation source](integrations/google-feedback/Code.gs)
- [GitHub Issues](https://github.com/lordkeremello45/HWcontrol2.0/issues)

If you report a hardware problem, include the OS, architecture, CPU/GPU model, driver version and relevant telemetry. **Never include passwords, API keys, bridge keys, signing credentials or private tokens.**
